# Eric Hart 个人网站

这是一个保留 vCard3 视觉布局、由 GitHub Pages 免费发布的静态个人网站。

## 中文内容管理后台

网站使用 [Pages CMS](https://app.pagescms.org/) 编辑内容。CMS 通过 GitHub App 获取仓库权限，保存时直接创建 Git 提交；网站代码中没有、也不需要保存 GitHub 令牌。

首次使用：

1. 打开 <https://app.pagescms.org/>，选择“使用 GitHub 登录”。
2. 按提示安装 Pages CMS GitHub App；仓库范围选择“仅选择的仓库”，只勾选 `eric-hart-ex.github.io`。
3. 在 Pages CMS 中打开 `eric-hart-ex/eric-hart-ex.github.io` 的 `main` 分支。
4. 打开“个人网站资料”，修改后点保存。保存会更新 `data/profile.json` 并提交到 GitHub。
5. GitHub Pages 通常会在几分钟内自动发布。可在仓库的 Actions 页面查看 `pages build and deployment` 状态。

目前可视化编辑：首页个人资料、学历信息、职业履历、专业技能和联系方式。`data/projects.json` 与 `data/posts.json` 是为作品和博客预留的数据接口，当前为空，也没有接入现有页面，因此不会改动现有作品和博客正文。

## 内容与页面关系

- `data/profile.json`：CMS 管理的结构化资料。
- `assets/js/site-content.js`：读取资料并更新现有 vCard3 页面。
- `.pages.yml`：中文编辑表单及保存规则。
- HTML 中保留当前文字作为备用内容；如果资料文件暂时无法加载，页面仍能正常显示。

## 发布与回退

Pages CMS 的每次保存都是独立 Git 提交。要回退误改，可在 GitHub 提交记录中打开对应提交并选择 Revert；回退提交合并到 `main` 后，GitHub Pages 会再次自动发布。


## CMS 扩展：技术博客与项目作品（2026-11）

本次在**原有 Pages CMS 项目**中增加栏目，无需新建仓库或部署独立服务器。管理入口仍是 <https://app.pagescms.org/>，使用你原来的 GitHub 授权、仓库、main 分支；仓库中的配置文件仍是 `.pages.yml`。

### 技术博客：文章管理

进入 Pages CMS → **技术博客 · 文章管理** → 在 `data/posts.json` 的列表里添加一篇文章：

1. 填写文章唯一标识 `slug`（仅英文小写/数字/连字符，例如 `google-seo-index`；发布后不要修改），标题、发布日期、分类和文章摘要。
2. 选择封面图片，使用 **正文 · 富文本编辑器**撰写文章。该编辑器支持标题层级、加粗、斜体、图片、列表、链接、引用等；正文以 HTML 保存。文章整体的**字体、字号、对齐**另有独立的选择字段（14/16/18/20px，左/中/右/两端对齐），用于保证不同终端显示稳定。
3. 可选填写 SEO 标题和描述。
4. 将“公开发布”勾选为 `true`，保存到 GitHub 后，前台 `blog.html` 自动读取文章列表，文章详情链接为 `single-post.html?id=你的slug`。未勾选不会出现在列表及详情页。
5. 想撤下文章时取消“公开发布”并保存；想重新编辑则打开原条目，保存后网站自动更新。请不要使用重复的 slug。

**注意：** Pages CMS 的富文本工具栏具体是否支持单段的字号、字体和对齐，取决于其当前编辑器版本；本站已实现“整篇”字体、字号与对齐的显式配置，并保留正文富文本已有的局部对齐/色彩/字号安全样式。没有增加单独的 TinyMCE/Tiptap 后台，也不需要再次登录。

### 项目作品：作品管理

进入 Pages CMS → **项目作品 · 作品管理**，新增条目，填写唯一 slug、标题、分类、封面、项目背景、富文本详细介绍和相关链接；勾选“公开展示”后，`works.html` 展示为可按分类筛选的卡片。未发布不会展示。

### 发布、预览与数据安全

- Pages CMS 保存会创建 GitHub 提交并触发 GitHub Pages；部署通常不是即时的，可在 **Actions → pages build and deployment** 查看进度。
- `data/posts.json` 和 `data/projects.json` 均保留在原仓库，最初都是空数组 `[]`，因此发布前列表显示“整理中”，不会继续显示模板的虚构文章和作品。
- **重要隐私限制：** 此仓库是公开静态网站，`published: false` 仅控制网页是否显示；草稿仍保存在可公开访问的 JSON 文件里，**不具有保密性**。不要把尚未公开的机密、客户资料、合同、密码或个人隐私填写到草稿中。如需真正私密草稿，应使用私人仓库/独立草稿存储与安全发布机制。
- 博客正文使用受限 HTML 标签与链接白名单渲染，阻止脚本和事件处理属性进入页面。作品链接限定 HTTP(S)。
- 本次保留了原有 vCard3 网站、首页和职业履历的 CMS 控制及导航，仅补齐博客和作品的数据联动。作品和博客的**默认占位内容未迁移**，也没有生成任何虚假的文章。
- 文章正文的SEO元标签由浏览器加载文章后更新；如未来需要更完整的搜索引擎抓取和社交平台分享预览，可增加 GitHub Actions 静态生成独立文章 HTML，这一步尚未实现。


## 传统工具栏式文章编辑 + 图片/短视频封面

在**同一个仓库**新增 `article-editor.html`，提供接近 Word 的顶部工具栏编辑器（标题/字体/字号/颜色/加粗/斜体/下划线/左右与两端对齐/列表/超链接/图片/表格/撤销/重做），以及文章标题、分类、SEO标题、日期等字段。

- 打开 <https://eric-hart-ex.github.io/article-editor.html> 即可使用；无需再次登录，**不是新的CMS后台**，也没有连接私人GitHub令牌。
- 页面自动在**当前浏览器本地**暂存草稿，不同步其他设备，不代表发布成功。点击「复制正文HTML」后，去现有 <https://app.pagescms.org/> → 技术博客 → 新增/编辑文章 → 正文的 **Source** 模式 → 粘贴 → 在 Pages CMS 完成保存。也可以下载文章JSON备份，再手动导入/编辑。
- 当前官方托管版 Pages CMS **不能把这套工具栏直接嵌入/替换其内部的富文本控件**；这是与原仓库兼容的独立编辑页。真正实现一键保存需要另行配置安全的服务端GitHub OAuth授权或自托管CMS，不能在公开GitHub Pages页面硬编码Token。

### 图片与5–10秒视频封面

Pages CMS **技术博客**和**项目作品**都新增：
- `cover`：图片封面/视频海报图；
- `coverType`：`image` 或 `video`；
- `coverVideo`：可选的 MP4/WebM视频路径。

上传媒体使用原仓库的 `assets/img/` 与新增 `assets/video/` 目录。视频建议5–10秒、无声、压缩后尽量小（建议低于5MB），上传视频时**同时上传一张静态图片**作为播放失败/减少动态效果时的回退图。

前台博客列表、文章详情与作品卡片会在 `coverType=video` 且视频路径有效时显示短视频：静音、循环、内联、可见时播放、离开屏幕暂停；尊重访客系统的「减少动态效果」。浏览器阻止自动播放或视频加载失败会继续显示静态海报图。

**提醒：** 这里只处理封面视频，不是长视频托管、视频编辑或自动剪辑功能。5–10秒属于上传建议，不会自动截断视频。GitHub Pages/CDN仓库储存视频有容量与流量限制，避免上传大量高码率视频。
